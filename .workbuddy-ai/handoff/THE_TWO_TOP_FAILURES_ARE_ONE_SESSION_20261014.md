# 头号与次号失败是同一条会话里的同一段流程 —— 但顺序**未确立**（2026-10-14）

> 实测：`GIANT_BEAST_SEARCH_NOT_PROVEN` 与 `BEAST_TARGET_SELECTION_NOT_PROVEN`
> 在**同一次运行**里一起出现的频率是**独立假设的 6.66 倍**（1115 个 run）。
> ⇒ 它们是**同一条会话的同一段野兽流程**，不是两个互不相干的缺陷；
> 把它们当两个优先级会**重复计算同一件工作**。
> **顺序（用 `recorded_at`）**：A 先，B 在 **28–85 秒**之后 —— 143/143。
> 我先前用 `step_id` 得到的"B 在前、相隔 ≥100 步"是**反的**，见第三节。

## 一、次号失败 `BEAST_TARGET_SELECTION_NOT_PROVEN` 的形状（全量实测）

- 按天：`10-05:1 · 10-06:1 · 10-07:2 · 10-08:7 · **10-10:90** · 10-11:45` —— 与头号失败**同一个尖峰**。
- 按 revision：`abe67449`(10-10) 84 · `2b85647a`(10-11) 45 · 其余 ≤3 —— 与头号失败**同一批版本**。
- 技能：`SELECT_BEAST_TARGET_MAMMOTH` 143 · `SELECT_BEAST_TARGET_LABELLED` 3。
- **`verifier_evidence` 不是空的**（与头号失败不同）：143 条全是
  `{"before_visible": true, "after_card": false}`，另 3 条是
  `{"before_identity": ["FROST_SCALED_RUNNER", 20], "before_labelled": true, "after_card": false}`。
  ⇒ **判决本身说得清楚**：点之前"目标可见"，点之后"卡片没开"。
- `state_before.page = MAP` ×146，`state_after.page = MAP` ×146 —— 全程没离开地图。
- `decision_reason`：`verified_visible_mammoth_target` ×143 / `beast_labelled_on_the_map…` ×3
  —— 决策之所以选它，是因为**视觉层报告看见了一个可见的猛犸目标**。

⇒ 也就是说：**视觉说"那儿有个目标"，点下去却没开出卡片。** 要么是误检，要么是点没落到目标上。

## 二、它和头号失败是**同一条流程**（这是本轮的主结论）

对**整条流**的 1115 个 run 统计：

| run 的个数 | 值 |
|---|---:|
| 有 A（`GIANT_BEAST_SEARCH_NOT_PROVEN`） | 164 |
| 有 B（`BEAST_TARGET_SELECTION_NOT_PROVEN`） | 146 |
| **两个都有** | **143** |
| 观测到的共现率 | 0.128 |
| 独立假设下应有 | 0.019 |
| **比值** | **6.66×** |

（只看 10-10/11：521 个 run，A 150 / B 135 / 都有 134，比值 3.4×。）
而 run 本身很短（episode 数 median 5、**max 29**）⇒ 两者同时出现意味着它们在**同一次短会话内**。
（另：143 个共现 run / 521 ≈ 与"10-10/11 的 run 数"相符，说明这个共现集中在尖峰那两天。）

⇒ **推论（可据以行动）**：修其中一跳很可能同时移动另一跳，**把它们列成两个优先级会重复计算**。

## 三、顺序：**A 在前，B 在 28–85 秒之后** —— 而且 `step_id` 给的是**反的**

我先用 `step_id` 得到过两句**错话**（"B 总在 A 之前 143/143"、"相隔 ≥100 步"），
它们建立在 `step_id` 上，而它的 per-run 语义不可靠：run 的最大 episode 数只有 **29**，
却出现 `step_id=204`（run `20261005_214645_278302` 同时带着 `step_id=4` 与 `204`），
另一些 run 又从 1 连续编号。

**换成本文件自己指定的那把尺子（`recorded_at`）重做，结论如下（143 个共现 run）：**

| 判据 | 结果 |
|---|---|
| 先后 | **A first 143 / B first 0** |
| 两次首败的间隔 | min **28 s** · median **33 s** · max **85 s** |
| 分布 | **全部落在 28–85 s 内**（没有一条 <0、也没有一条 ≥120 s） |

⇒ **`GIANT_BEAST_SEARCH_NOT_PROVEN` 先发生，`BEAST_TARGET_SELECTION_NOT_PROVEN` 在
28–85 秒之后发生** —— 也就是 polar 会话先跑搜索（找不到），紧接着同一段流程去点一个
"视觉声称看得见"的猛犸目标，而那一下没开出卡片。

**两把尺子在"多少次"上一致（143/143），在"方向"上相反。**
这就是为什么"先用可疑字段算结论、再回头怀疑字段"会得到一个**看起来同样干净**的反向答案。

（未主张因果：28–85 s 的紧窗口与"相邻两跳"一致，但它仍然是**时间在先**，不是**因果证明**。
要证因果需要在真机上打断其中一跳看另一跳是否消失 —— 设备锁在 MANUAL，本轮做不到。）

## 四、据此能说 / 不能说

- **能说**：两者是同一会话里的同一段流程（共现 6.66×，run 很短）；
  **A 先、B 在 28–85 秒后**（`recorded_at`，143/143）；次号失败的含义是
  "视觉报告的目标被点了却没开卡片"，且判决带了证据。
- **不能说**：**因果**（28–85 s 只证时间在先）；也**不能说**其中一个引起另一个 ——
  也可能是**共同的上游**（例如该海域当下没有可打的猛犸：这与头号失败"搜索返回空"的结论方向一致，
  但**未证**）。
- **§10 分类未定**：若上游是"当下没有目标"，则两者都属 `EXPECTED_NO_ACTION`（正常，换 Goal）
  而不是 `CAPABILITY_GAP`；判定它需要**一帧真机** —— **设备锁在 MANUAL，本轮做不到**。
