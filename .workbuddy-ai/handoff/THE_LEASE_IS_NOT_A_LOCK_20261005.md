# 租约不是锁：一次探针撞坏了一步生产（2026-10-05 23:30）

> ## ⚠ 本标题已在 23:35 被自己的证据推翻 —— 结论更正
>
> **租约是好的。** 用 before 帧时间戳判定：那一步失败（`OPEN_HOME` 15:30:56）的 **before 帧拍于 15:30:41**，
> 即**在租约取得（15:30:48）之前 7 秒** —— 那一轮循环在守卫之前就已经开始，守卫在**每轮开头**查，
> 所以它照走完该步；**而探针此时已把客户端挪到活动页** ⇒ 它按"我在 MAP"点回城，落到 EVENT。
> 且从我取租约到我释放（15:31:11）之间**只有那一步、之后没有新 episode** ⇒ **循环在后面几轮确实让路了**。
>
> 守卫的条件（`runtime.py:9057`）是 `held.owner != OWNER_GAMEPLAY and not self._owns_the_lease(held)`，
> **对任何非 gameplay 持有者都生效**；它的语义就是 docstring 那句 *"hands the device over **at a safe point**"*。
>
> **真正的缺陷在探针的时序：它 `acquire` 之后立刻动手，而当时还有一轮在飞（本项目约 13–15 秒一轮）。**
> 正确做法：**取租约后先等"账本安静"（≥ 一个循环周期，约 20 秒无新 episode）再碰设备。**
> 下面正文保留原样，作为"一个把结论下得太早"的记录。

**一句话**：我用项目自己的 lease-aware 工具去读巨熊开窗时刻；工具规规矩矩地取了租约、跑完、放回租约，
**但 AUTO 循环在租约期间照样发步**，两边导航互撞 —— 循环失败了一步，而**那一步是我造成的**。

## 现场（全部可复查）

租约轨迹（`learning/device_leases.jsonl`）：

```
acquired | DEVICE_BEAR_BASELINE_NEWACCOUNT | 2026-10-05T15:30:48
released | DEVICE_BEAR_BASELINE_NEWACCOUNT | 2026-10-05T15:31:11 | result=DONE
```

生产账本（`learning/episodes.jsonl`）同一窗口：

```
15:30:41  OPEN_MAP   SUCCESS     ← 取租约前
15:30:56  OPEN_HOME  FAILURE     ← 【租约期间】8 秒后仍然发步
            failure_type = OPEN_HOME_NOT_PROVEN
            duration     = 8.67 s
            before page  = MAP
            after  page  = EVENT    ← 我的探针把客户端带到了活动页
            reason       = training_goal_requires_home
```

循环的账本是自洽的：它 `15:30:41` 刚 `OPEN_MAP`，于是按"我在地图上"去点回城；
**而那一刻客户端已经被我的探针带到了活动页**，于是落到 EVENT、判定 `OPEN_HOME_NOT_PROVEN`。
**⇒ 这一条失败由探针造成。**

探针自己的账本（`learning/bear_baseline_newaccount_pass11.json`）：

```json
{ "scores": [0.6846, 0.7215], "matched_at_step": 1, "match_score": 0.7215,
  "page_text": "欢迎来到 联盟争霸赛 【联盟争霸赛】中派遣的部队不会损失或重伤，请放心报名。 点击任意位置退出",
  "reserve_raw": null, "returned_to_city": true }
```

⇒ **没有到达巨熊页**：`0.7215` 是**假阳性**（白卡片也能对上），点下去撞到一张 **联盟争霸赛弹窗**，
`预约自动开启` 读回 `null`。

## 结论一：租约协议是好的，但它**不是锁**

- 工具侧完全正确：取租约 → 干活 → `finally` 里放回 → 状态回 `V2控制中`。
- 循环侧**没有让路**：`runtime.py` 里有 6 处 `held = self.device_lease.holder()`（1183 / 2627 / 6712 /
  6773 / 9057 / 9342）与 `_owns_the_lease()`，注释说租约是"唯一声明所有者名字的地方"；
  **但这条主步进路径上显然没有"看到外来持有者就不发动作"的守卫。**
- 这与记忆里那句自有陈述一致：**"取租约的一方仍未写"** —— 至今仍然成立。

## 结论二：因此的行动约束（在租约变成真锁之前）

1. **循环在跑时，不再做任何真机探针** —— **哪怕走租约**。租约现在只能证明"我声明了"，
   不能阻止循环发步。
2. 要真机读数，只有两条路：
   - **让操作者暂停循环**（10 秒的事），或
   - **先做"让路"守卫**，再探。
3. 判据仍然用那三条非侵入法：账本 mtime / 两帧对比 / `control_panel/*.json` mtime。

## 结论三：下一步（新问题 ⇒ 按硬门先出搜索产物，再动手）

把租约变成**真锁**：在**发步之前**查 `holder()`，非自己持有则本 tick 不发动作。
**本项目已有这条形状的先例**（`runtime` 里 `device_leased_for_development` → `steps: []`），
所以这是"照抄已有形状"，不是新机制。

**要先量的三件事**（决定改哪儿）：
1. 那 6 个 `holder()` 读取点**各在哪条路径**上（哪条拦住了、哪条没拦）；
2. 主步进路径**为什么漏掉**（是没查，还是查了但放行）；
3. 已有那条"让路"（`steps: []`）**在哪一层**，新的守卫应当放在同一层。
