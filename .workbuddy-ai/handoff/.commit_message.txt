feat(handoff): cross-account handoff mechanism + git baseline

Any WorkBuddy account must be able to take over this project with no chat
history.  Static Markdown rots as soon as code changes, so the handoff is
generated from real project state instead of copied from yesterday's notes.

- git: first version-control baseline.  The project had none, and an accidental
  deletion of 15 exploration scripts was therefore unrecoverable.
- tools/update_workbuddy_handoff.py: reads git, the live registry, the
  capability mapping, the episode stream, the runtime snapshot, the newest log
  and the evidence integrity check.  Rewrites 01_CURRENT_TRUTH.md,
  08_LIVE_METRICS.json and 09_RUNTIME_STATE.json in full, and refreshes only the
  <!-- AUTO:id --> blocks in 02/03/04/05/10, so hand-written reasoning is never
  overwritten.  No number in the output is hard-coded history.
- START_HERE.md: the single entry point for a new account, including the
  environment traps that cost hours if unknown (the shell has no coreutils,
  PowerShell stdout is swallowed, PIL lives only in the project venv).
- .workbuddy-ai/handoff/: 11 files split into machine-generated truth and
  hand-written judgement, including the master rules extracted from the takeover
  directive and a decision log of the non-obvious choices.
- tools/verify_handoff.py + tests/test_handoff.py: the handoff's structural
  invariants are now enforced, with a negative control so the audit cannot
  silently pass on a broken directory.
- .gitignore: exclude ~1.1 GB of rotating screenshot evidence by FILE pattern
  (never by directory pattern, which would silently drop the regression
  fixtures) and the nested third-party clones.

Verified: 85 tests pass; all handoff invariants pass; regeneration is idempotent
and survives a simulated sudden disconnect (generated files deleted, AUTO blocks
emptied, regenerated byte-identical apart from the timestamp).
