**审查结果（改动前）**：**6 PASS / 2 FAIL / 4 UNMEASURED**。两个 FAIL 正是总则 §5 点名的：
- `NO_PERMANENT_UNKNOWN_BLACKHOLE`（`启用Goal → UNKNOWN → priority=-inf → 永远没人再看`）

**查证已有机制（§14）**：`candidate_policy.CandidateAttemptPool` 已是 "persistent starvation counter
consumed by the one Scheduler"，但 `eligible()` 要求 `SkillState.CANDIDATE` ⇒ **不覆盖无 skill 的
UNKNOWN** ⇒ 那一类**从来没有被任何机制算过**。所以不是"已有机制没接线"，是"这一类根本没被考虑"。

**修复**：`goal_utility.observation_ticket()` + `rank()` 的门 + `utility()` 的 `-inf` 分支。
- 只对 **UNKNOWN** 生效（COMPLETE / BLOCKED / SCHEDULED_NOT_OPEN / EXPIRED 仍 `-inf`）；
- 只对**声明了 `evidence["required_observation"]`** 的生效（§5 后半句：只有能说清"在等什么"才准留在板上）；
- 上限 **300**（落在 routine 70-250 与 intel 800 之间），**观察票不是许可** —— 能不能动仍归
  `capability_bootstrap`（拒绝消耗/集结/购买动词）与 capability gate。

**修复后**：**9 PASS / 0 FAIL / 4 UNMEASURED**；ROLE_A 6 选 5、ROLE_B 5 选 4。剩下的是
BLOCKED-带-condition 与 SCHEDULED_NOT_OPEN —— **等待，不是丢失**。
