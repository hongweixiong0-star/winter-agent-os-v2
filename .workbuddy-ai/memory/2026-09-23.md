x=225 = 0.3125，是**面板文字列**；行的蓝色箭头在 x≈480（0.666）。同一坐标一次打开动作栏、一次

## 三、判据一律来自"帧上这条证据是谁画的、在哪一层"

- 训练按钮可开训的两个证据：**标签** `训练`（y 0.862）或**它自己的预计耗时**（y 0.888，在动作栏内部）；
  而**运行中**那一页右侧按钮写 `加速`、队列倒计时画在动作栏**上方**（y 0.732，旁边有 `训练中`）。
  ⇒ 动作栏内部的裸倒计时 = 按钮的 caption，是"按钮已画出"的证据。
- 归档 70 张训练帧对照：**5 张由 UNKNOWN 变 AVAILABLE/trainable=True，无一张反向变化**；
  另 27 张只是多了 `train_button_basis` 字段。
- 层级顺序的三条原则（本轮实测得出）：
  1. 模板命中优先（`live_train_selection_available.png` 一直是模板路径，把它压掉就是回归）；
  2. **本帧读数**（行按钮像素、按钮 caption）优先于**词位置**——词说的是"这一行叫什么"，不是"控件在哪"；
  3. 词扫描的 `ABSENT` 会终止链条，所以"手挡住了词但按钮确实在"必须在它**之前**回答。
- 两处基据命名共用：`QUICK_PANEL_ARROW_BASIS_SCAN` / `_ESTIMATE`（ocr.py 定义，brain 比较常量）。

`g≥150 且 g−r≥50 且 g−b≥50`，约 41×31 px。

## 一个反直觉的实测结果（推翻了我第一版的优先级）

我先写了"找到蓝箭头就不找绿勾"，结果 16:41 射手行与 22:02 我的奖励行都读成 `ARROW` ——
因为**那两行的蓝色元素同时存在**。逐像素量过：射手行蓝只有 1px 噪声（在 dy=−8 处有 19px 的窄条），

⇒ 结论：**绿勾才是这些行的身份**，蓝那点像素不足以证明"这是进入箭头"。改为绿勾优先。

## 接上的执行路径（新）

| 层 | 内容 |
|---|---|
| 读取器 | `rows[]` 增 `control` = `ARROW`/`DONE`/`NONE`、`done_norm`、`done_box_norm`；**每行都找绿勾**，不只是蓝扫描失败的行 |

| 大脑 | `_claimable_panel_row` + `_QUICK_PANEL_ROW_CLAIM_SKILL`；**指定兵营的 Goal 只领自己那一行**；进入路径要求 `control == ARROW`，所以绿勾行不会被当进入目标 |

## 第三段 — 真机按下绿勾：一个负面结果，以及它逼出来的两处修正

提交 `efc0ed5` 之后的真机轮（持租约、`--goal TRAIN`）：

```
17:50:59 COLLECT_FINISHED_TRAINING_SHIELD  tap=[404, 556]   ← 正是绿勾中心 (0.5618×720, 0.4344×1280)
17:51:02 该步 SUCCESS（当时验证器判通过）
```

**但"通过"是错的**：后帧显示面板**整块关闭**，没有奖励弹窗；把面板重新打开时（17:53:39、
17:54:12、17:54:28 三处读数）盾兵行**仍然是 `已完成 / control=DONE`**。也就是说按绿勾什么也没领到。

### 由此修的两处

1. **验证器的"通过"是"我们不再看了"换来的**。旧判据 `tick_gone = before==DONE and after!=DONE`
   在面板消失时也成立（读不到行 ⇒ after 的 control 是空串 ⇒ ≠ DONE）。现要求
   `panel_readable_after = bool(after.quick_panel["rows"])`，并把该字段写进 evidence。
   ⇒ 面板消失是它自己的结果，不是领取证据。
2. **领取路径暂时清空**（`_QUICK_PANEL_ROW_CLAIM_SKILL = {}`，附长注释说明理由）。
   保留读数、四个技能、验证器与词典记录；但不让大脑发出这个动作，因为：
   - 每轮保证失败一次；
   - 每轮白白关掉一次面板；
   - **决定性的一条**：十次这样的 episode 会触发项目自己的"无进展即延后"，把**整个训练 Goal**
     按 `OPEN_TRAINING_PAGE|NO_GOAL_PROGRESS` 延后 —— 代价远大于想赢的那次领取。

词典四条记录里 `what_tapping_it_does` 已改为实测原文（落点在绿勾、面板关闭、无奖励弹窗、
重读仍 已完成）；`control_identity` 补上"点确实发出去了、客户端没有领取"。

**下一步的候选**（写进代码注释了）：已完成行走**它自己的页面**——它不画蓝箭头，所以需要行自身
的框或另一次渲染；找到真正领取的控件后，把行 key 填回那张表。
