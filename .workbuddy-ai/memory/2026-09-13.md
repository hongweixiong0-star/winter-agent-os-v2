## 目标体系梳理 + 覆盖率度量失真（重要发现）

### 目标是怎么来的
`winter_agent_v2/goal_library.py` 的 `GoalLibrary.discover(world)` **从观测动态发现目标**，不是硬编码任务表。
- 状态枚举：DISCOVERED / READY / IN_PROGRESS / COMPLETE / BLOCKED / UNKNOWN。
- 优先级 = `deadline_pressure + reward_value + daily_loss + event_synergy + development_value - resource_cost - risk`。
  COMPLETE/BLOCKED/UNKNOWN 直接 -inf（不可行动）。
- `deadline_pressure` 是分段阶跃：<2h=10000、<6h=4000、<12h=2000、<24h=1000、否则 100；过期 -100000。
  → 临近截止会压倒性抢占，这是刻意的。
- `best()` 只选 `priority != -inf 且 available_skills 非空` 的目标。

### 两套配置开关（都在 config/）
- `policy_state.json`：8 个 goal_categories 全开（日常低保/持续发展/联盟协作/限时活动/PVE/实时活动/资源优化/自动学习），
  reward_policy=FREE_CLAIM_FIRST，real_money=PERMANENTLY_BLOCKED。更新于 09-13 20:40。
- `control_panel_state.json`：8 个 task 全开（邮件/探险/采集/训练/Intel/联盟/日常/野怪），continuous=true。更新于 09-13 20:38。

## PHASE E 突破：资源 tab 模板系统性错位（21:00-23:20）

### 重大缺陷（已修复）
`SELECT_RESOURCE` 在所有失败 episode 里报 `SEMANTIC_TARGET_NOT_VERIFIED`（Top failure 之一，10 次），
根因不是模板缺失，而是**模板 ROI 差了一整个 tab**。

- 真机实测 tab 中心：`BEAST 0.101 / MEAT 0.286 / WOOD 0.471 / COAL 0.656 / IRON 0.841`（间距 0.185）
- manifest 里手写的 ROI：`MEAT 0.20 / WOOD 0.41 / COAL 0.62 / IRON 0.82` —— 每个都偏左约 1/3 tab
- 后果：`RESOURCE_TAB_MEAT` 里装的其实是**木材**图标；`RESOURCE_MEAT_SELECTED` 在木材选中的帧上判定为 MEAT。
  这个错误**自洽**，所以从来没被发现：selector 说 MEAT，policy 要 MEAT，verifier 比对两者 → PASS。
  典型的"假证据链"。

### 测量方法（可复现）
白色选中括号（L 形角标）的粗白竖臂是唯一可靠锚点。把 4 张 `..._selected_<res>_...` 帧的粗白列取交集
得到噪声臂 {0.006, 0.024, 0.074, 0.115}（HUD/水印），差集就是真实括号臂。
排名后得间距 0.185，据此推全部 5 个 tab 中心。
