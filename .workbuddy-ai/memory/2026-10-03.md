## WB-1002-42「账本 50 分钟没更新」是假的 —— 我把 UTC 当成本地时间（第二次犯）

**症状**：接上一轮收尾，账本最后一条 `03:19:26Z`，看��� `now()` 是 `11:20` ⇒
"停了 50 分钟"，于是去跑 `tools/measure_auto_uptime.py`。

**先证伪**：`dataset/raw/control_panel/runtime_auto/` 里**11:24:14（5 秒前）还在写**，
81 个文件；`episodes.jsonl` 的 mtime 也是 `11:24:20`。**生产一秒都没停。**

**根因**：`recorded_at` 是 `2026-10-03T03:24:20.256086+00:00`（**带 `+00:00` 的 UTC**），
而我拿字符串眼估"03:19 对 11:20"⇒ **差8 小时**。
**记忆里已记过一次"13:35Z 被读成 13:35 本地"，这次换了形式复发：不是没看时区标记，
而是拿UTC 字段与本地 `now()` 直接比。**

> **规则：任何"账本多久没动 / X 分钟没有记录"的判断，
> 必须用同一个带时区的对象做差，不能拿UTC 字段和本地时钟眼估。**
> 可直接用的两行（都返回同一事实，互为交叉验证）：
> ```python
> dt=datetime.datetime.fromisoformat(last["recorded_at"])       # 自带 tzinfo
> datetime.datetime.now(dt.tzinfo) - dt                         # 正确的"距今"
> datetime.datetime.fromtimestamp(os.path.getmtime(path))# 文件侧交叉验证
> ```
> **`os.path.getmtime` 是最便宜的哨兵**：账本没写 ⇒ mtime 不动；
> 它不动而 run 目录在动 ⇒ 停的是写入方而不是执行方。**先看它，别先写结论。**

**为什么这条值得单独记**：它和「长时间看起来停了先跑测量工具」是**同一条铁律的两面**——
那条说"别急着判停，去跑工具"；这条说**"判停的证据本身也可能是错的"**。
两条合起来才是完整判据：**先证伪观测，再解释观测。**

## 2026-10-03 15:48-16:20 第十九轮：承诺机制已存在，但它答的是另一个问题（无代码改动）

### 先查"项目是否已有这个机制"—— 有，但语义不同
`runtime._committed_goal`，它自己的注释（733-736）写明用途：
**"在页面自身发现不到任何目标时，episode 记在谁名下"**（采集路线开搜索结果后每一步）。
消费方全部是**记账/续作**用途：
`_step_goal` 兜底归因、`8210` 传给 session 当归属字段、
`6059`/`6487` 判断日历续作是否仍是选中任务。
**没有一个是"继续做"。**

### 而且它**结构上无法**表达这个承诺
`8758`：`self._committed_goal = best_goal.goal_id` —— **每个 tick 都被覆盖**，
而 board 每步重排 ⇒ "承诺者"永远是最新一次排序的赢家，
**而那 24 秒的重排正是抹掉承诺的东西**。

⇒ **不能再加第二个承诺字段**（= 第二份真值，宪法禁止）。
⇒ 缺的不是机制，是**一个决定**：到达后谁拥有这一页、拥有多久。

### 可行性已确认（这是本轮的关键测量）
如果导航后页面几乎没动，就没有"到达"可言。
实测全量：**1323 个 `OPEN_MAP`/`OPEN_HOME` 步中 1282 次（97%）下一页真的换了页**。
⇒ **跳步真的发生、页面真的变了、确实有一个"到达"可以被拥有。**
⇒ 窗口**恰好一个 tick 宽、且完全确定** ⇒ 最小修法可行：
**发出导航的那个目标就是付了路费的人，跳步后的那个 tick 是它唯一能花掉所有权的地方。**

### 还没定的一件事（不能猜）
**一个"所有者"值多久**：
- 一步 ⇒ 能破环，但可能饿死需要两步才能推进的目标；
- 无界 ⇒ 会让目标占着一页它做不了事的地方
  （这正是 retry / fairness 项要防的失败）。
