### THE LAW: the client eats the first motion after touch_down

World-map drag, one held finger, capture after every move:

    cmd +40 -> measured   0     the FIRST move is consumed whole
    cmd +60 -> measured  60     pixel exact
    cmd +60 -> measured  60     reproducible
    cmd -40 -> measured -40     exact both ways
    holding still -> 0 ; after release -> 0 ; move after release -> refused

So every continuous session must open with a throwaway **ENGAGE** move whose
displacement nobody depends on. `ContinuousTouchSession`/`VisualServoSession` do
exactly that (`engage_move_px`). In the fishing level the same absorption shows up
as ~5 ticks of no response before the line starts moving.

## 3. New modules (extensions, not a second architecture)

* `winter_agent_v2/maa_executor.py` — `touch_down/move/up`, `touch_balance`,
  `touch_trace`. Same discipline as `click`: production gate, `ensure_ready`,
  per-verb latency stats, machine-readable error reason.
* `winter_agent_v2/continuous_touch.py` — one held finger with a guaranteed
  release. Invariant: a session that is not IDLE/RELEASED/ABORTED has a finger
  down, and **every** exit path lifts it (normal, exception, `with`, GC, and
  `release_all()` for the watchdog). `_finger_down` tracks the PHYSICAL truth
  separately from the lifecycle state, so `abort()` cannot report a clean release
  after a failed lift — that bug was found by the offline test and fixed.
* `winter_agent_v2/visual_servo.py` — generic `capture → crop ROI → detector →
  controller → touch_move` loop. Protections in one place: dead zone, per-tick
  clamp, low-pass (seeded from the finger's actual position), lost-target
  hold/release, frame-stale guard (stops with `CLIENT_FROZEN` rather than steering
  blind), max duration. It calls nothing but capture + the caller's two callables:
  no world state, no scheduler, no OCR, no model (asserted by a test).
  It also publishes the actuator position into the state so an outer loop can close.
* `winter_agent_v2/fishing_vision.py` — line / hook / depth from pixels only.
* `winter_agent_v2/fishing_session.py` — `FISHING_READY → CAST_START → DESCENDING →
  ASCENDING → RESULT → COMPLETE` (+PAUSED/FAILED/UNKNOWN), with OBSTACLE_AVOIDANCE
  descent and FISH_HEAD_TRACKING ascent, plus a calibration mode.

### Bug found in my own helper
`frame_signature` originally SAMPLED pixels (`frame[ys][:, xs]`); a scene that had
clearly moved produced a change of **0.00**. It now area-averages via `resize`, which
gave 34.6 on the same pair. A stale guard built on the sampling version would call a
live client frozen.

## 5. Process notes

* Everything about the fishing UI came from real frames (capture-first). No ROI was
  guessed, and no detection was written before a frame existed to fit it to.
* Two runs were wasted by MY OWN errors, both now fixed: OCR (seconds per call)
  inside the capture loop left only 21 samples across a whole level, and a watchdog
  aborted on 4 lost ticks — the level's own ending — cutting control to 0.6 s.
* `dataset/raw/fishing_tournament/*/frames|key_frames` is 300 MB+ of dense captures
  and is gitignored; the small JSON reports next to them are the evidence of record.
* Careful git moment: the push was rejected because origin/main had moved 50 commits
  ahead. Rebased cleanly. 46 untracked files would have been overwritten by the
  incoming commits; they were backed up OUTSIDE the repo first, then compared —
  36/46 byte-identical, and the 10 that differed were all OLDER local copies of files
  the remote now owns (remote versions larger). Nothing local-only was lost.
* The pre-existing dirty working tree was stashed as
  `stash@{0}: wip-before-rebase-fishing` and deliberately **left in place** (not
  re-applied): it is volatile runtime state and re-applying it over 50 newer commits
  would regress it.

## 6. Open items

* `UPGRADE_FISHING_KIT` / free special mode / daily tiers / collection rewards are
  registered as goals but their skills are not implemented (they show up as

  anything but ENGAGE + steer will have no level left to control.
