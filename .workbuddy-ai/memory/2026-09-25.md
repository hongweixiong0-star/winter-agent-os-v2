# 2026-09-25 — 停止 WorkBuddy 通道，改用本地 Qwen 做结构化 UI 动作

## 方向变更（操作者指令，本轮最高优先级）

**正式停止** V2 通过本地网关 / 开放平台 / OAuth / 会话桥接调用 WorkBuddy 桌面端模型。
WorkBuddy 退回为**人工直接使用的开发工具**。UNKNOWN 的作答改由**本机已部署的本地 Qwen**
在循环内完成：调度器决定**做什么**，Qwen 决定**怎么做**（输出结构化 UI 动作，不是坐标）。

### 实施（都是最小改动，没有新增第二套架构）

| 位置 | 改动 |
| --- | --- |
| `winter_agent_v2/local_qwen.py` | **新**：全项目唯一知道模型地址的文件。Ollama `/api/chat` + `format=json` + `num_ctx=8192` + `think=false`；`ask_json` 返回结果对象、从不抛异常；调用与失败全部落 `learning/local_qwen_calls.jsonl` |

| `tools/run_live.py` | 从 config 建 planner 并注入 Runtime |

| `winter_agent_v2/unknown_dispatch.py` | `worker(submit=...)`：`False` 时只 reconcile 并报 `WORKBUDDY_CHANNEL_RETIRED` |
| `tools/unknown_ai_worker.py` | 读同一个开关；`--once`/`--loop` 只 reconcile，并**明说**是退役而不是坏了 |

**关键设计：复用现有答案协议，不建第二套。**
Qwen 的 plan 被翻译成项目**已有的** `unknown_advisor.Advice`（`action_kind=ACTION_ORDINARY`，
`target_anchor={"text": 客户端自己印的字}`）。于是下游的 grounding / 消耗风控 / 语义命名 /
执行 / verifier / 知识归档**一行没改**，换掉的只是"答案从哪来"。
`ManagedAdvisor` 就是那个 drop-in（`take_request` / `ask` / `read_request` / `pending`）。

**坐标不经过模型。** packet 里每个元素只有 `id / text / area`；回复里出现任何几何键
（`x/y/box/point/...`）由 `FORBIDDEN_KEYS` 递归拒绝并单独命名。落点由
`unknown_advisor.grounded_region` 在**同一帧**上从该元素自己的 OCR 框算出。
