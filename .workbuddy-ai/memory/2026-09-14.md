# 接管第四轮（DISPATCH_NOT_PROVEN 根因定位 + 验证诚实性修复）

## 根因（真机帧 + OCR token 双重证据）

COAL 验收全部步骤通过，只最后一步失败：`DISPATCH_MARCH → after_page=EVENT`。
但那张 `after` 帧**就是世界地图**，行军队列 `6/6`、5 条「采集中」——派兵其实成功了。

完整因果链（`tools/diagnose_map_event_misclassification.py`）：

1. 行军队列浮层盖住「搜索资源」按钮，`STATUS_*` 行模板也不匹配该布局
   → 模板层对地图返回 `UNKNOWN`；
2. `HybridVision` 回落 OCR 分类器；
3. OCR 读到地图右侧活动栏的**按钮文字**「常规活动」（置信 0.998）→ `Page.EVENT`，
   `marches=[]`、`march_used=None`；
4. `verify_wood_dispatch_from_march` 需要「地图 + 有行军在跑」→ 失败。

**这就是 28 次 `DISPATCH_NOT_PROVEN` 的来源。**

- 世界地图常驻锚点：`BTN_OPEN_HOME` 匹配 **且** `PAGE_MAP` 不匹配（主城显示的是地图按钮，
  两者互斥）。同一帧复验：`page=MAP marches=['GATHERING'] march_used=6`。
- OCR 规则删除「常规活动」——它是按钮标签。新原则写进 docstring：
  **玩家不在那个页面时也能看到的文字，不能用来判定页面。**
