**§6 -- a soak that declines says so.** `_drive_soak` returned silently when the launch context
was not production, so the window showed "尚未开始（GUI 启动后由窗口自行测量，无需任何手工命令）"

    尚未触发（GUI 启动后由窗口自行测量；若长时间如此即为异常，而非等待）
    启动失败：<真实原因>（不是「尚未开始」——窗口已尝试并给出了原因）
    运行中 FAIL · 0.0/15 分钟 / 1 样本 · 重启 1 个网关进程 · 黑窗 0 · 未通过：端口归属

i.e. the six states the operator asked for: 尚未触发 / 运行中 n/15min / PASS / FAIL / INCOMPLETE /
启动失败:<reason>.

**What the audit of §6 actually found, and did not find.** `launch_context()` returns
`production` for a window on the production interpreter, and `_drive_soak` creates the soak
correctly when called. The evidence file exists with `launch_context: production`. But it holds
**`sample_count: 1`** -- one sample per window -- and the window running at the moment of the
screenshot has no "验收 Soak 已启动" line in `panel.log` at all. So the soak did *not* run in
that window, and the reason was invisible by construction: that was the silent `return`. It is
no longer silent, which is the fix; whether the cause is the launch context or a later
exception will now be readable on the page instead of inferred from timestamps.
