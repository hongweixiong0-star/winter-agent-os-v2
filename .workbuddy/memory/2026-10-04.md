## 40GB 截图模板提取：第 2 件 — 小实验（只读，未改主代码）

**目的**：验证 40GB 历史截图里有没有可提取的稳定特征。

**抽样**：96 帧 / 8 页（HOME MAP EVENT POPUP INTEL BEAST MARCH MAIL）/ 3 天 /
**91 个不同采集会话**（96 帧来自 91 会话 ⇒ 几乎每帧都是独立一次观察）/ 统一 720×1280 RGB。

**踩坑（已修）**
1. `episodes.jsonl` 存的是 **C 盘 worktree 老路径**，40GB 搬到 E 盘后 `is_file()` 只剩 18 张
   ⇒ 第一版只采到 18 帧。按 `control_panel` 后缀重映射到 E 盘后恢复 19884 张。
2. 采集目录名是本地日期、文件名尾部时间戳是 UTC（差 8 小时）⇒ "天"按目录前缀算。

**方法**：逐像素中位数 → `stable_frac >= 0.80` → 连通域 → 面积 ≥400px。
双对照：同会话 12 帧 coverage 0.258 / 跨 8 页拼一组 coverage **0.003、0 区域** ⇒ 判别器有效。

**关键事故**：第一版 49 个框里，EVENT 给出**整帧**候选 score 0.947（假阳性）。
根因 = 连通域 **fill 仅 0.141**，散布的稳定行被形态学 `close` 串成贯穿整帧的链。
独立复算 EVENT 帧间平均差 **62.9**（八页中最大）⇒ 与"画面没动"完全相反。
补三道防伪（fill≥0.35 / texture≥3 / 非整帧）后 **49 → 29 个框**，假阳性清零，EVENT 归零。

**结果**：稳定性分布 0.80–0.85→10 / 0.85–0.90→5 / 0.90–0.95→10 / 0.95–1.00→3；
去重后 **21 个独立区域**；逐页 HOME 9 / BEAST 8 / MAP 6 / MARCH 6 / EVENT 0 / POPUP 0 / INTEL 0 / MAIL 0。

2. `episode_scan()` 有 mtime 缓存，**但 AUTO 持续 append ⇒ mtime 每次都变 ⇒ 缓存永不命中**，
