## 08:05–08:10 修复静默停摆：**一个坏事件不能结束 drain，也不能沉默**（已提交 `2b85647a`）

**根因（读代码定位，不是猜）**：`control_panel.py::_drain_events`

```python
try:
    while True:
        kind, data = self.events.get_nowait()
        if kind == "refresh": self._apply_world(*data)
        elif kind == "complete": self._apply_complete(*data)   # ← 若这里抛异常
        ...
except queue.Empty: pass
self.root.after(100, self._drain_events)      # ← 这一行就不会执行
```

`try` **只捕 `queue.Empty`**，而**重排在 `try` 之后** ⇒ 处理**任何单个事件**时抛出的异常都会让
**drain 整体断掉**；而面板跑在 `pythonw` 下 ⇒ **traceback 无处可去** ⇒ **完全静默**。
`_apply_complete` 一个函数就碰十几个字段、一次 funnel 刷新、一次写文件 ⇒ 足够成为触发点。
**⇒ 与观测逐条吻合**（07:52:30 还在启动、之后无日志、不排下一轮、`alive=True` 全程）。

**修法（只动循环，不动任何事件的含义）**：
1. **每个事件各自 `try`** ⇒ 一个坏 payload 被**点名**，批次继续（不再让一个坏事件吃掉后面全部事件）；
2. **重排移进 `finally`** ⇒ 即使 handler 自己失败，drain 也继续。

**测试** `tests/test_the_drain_survives_a_bad_event.py`（2 条）：
① 行为判据（异常被记录 + 重排 + **坏事件之后的事件仍被处理**）；
② **正向对照**：把旧 body **逐字**复现，断言它**不重排、且丢掉后续事件** ⇒ 证明①会咬。
（第一次跑**失败**了：stub 没有 `_drain_events` 属性 —— 而重排正要引用它；那正是这项测试要表达的东西。）

**落地**：`+43/−10` 于 `tools/control_panel.py`；`commit **2b85647a**`（2 files, +145/−10）
→ repin `RESULT: CLEAN_OUTSIDE_DATA` → `--check-only` `CODE_COMMIT=2b85647a WORKTREE_CLEAN=true`
→ 面板重启（pid **27024**，`runtime_loaded_revision = 2b85647a…`）⇒ **修复已生效，`AUTO_RUNNING`、`workers: 1`**。
回归：`test_control_panel.py` + 新测试 **71 passed**。

> **判据：一个"只在成功路径上重排自己"的循环，遇到任何一次异常就会永久停摆 —— 而它的现场是静的。**
> 这与 `control_panel.py:9357` 那句注释（*"a halt must never be silent"*）是同一条原则：
> 那次为「gate declined」补了日志，这次补的是「handler 抛异常」这条**唯一还没被覆盖的静默出口**。
> **判"还活着吗"看产出物新鲜度**（三个账本同停），不是看进程在不在（`alive=True`）。
