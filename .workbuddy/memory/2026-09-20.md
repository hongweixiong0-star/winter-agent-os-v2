## 12:12–12:30 — Soak 启动失败：**诊断与预期不同**，另修掉两个真缺陷

### 一、Soak 并不选择解释器（三向实测）
`_drive_soak` 是**进程内**构造 `GatewaySoak`（`gateway_soak.py` **不创建任何子进程**，它甚至断言 GUI
不额外 spawn 网关）。截图那句来自 `launch_context()`（`control_panel.py:1390`），它打印的是**窗口自己的**
`sys.executable`。三种情形实测：

| 启动窗口的解释器 | `launch_context()` |
|---|---|
| venv 的 python | `('production','运行解释器是生产解释器同目录的 python.exe')` → **Soak 启动** |
| 带 `WINTER_AGENT_LAUNCH_PATH=desktop` | `('production','正式桌面入口')` → **Soak 启动** |
| 其它解释器 | `('development','运行解释器 … 不在生产解释器目录 E:\无尽冬日智能体\.venv\Scripts 内')` ← **截图那句** |

⇒ **Soak 拒绝是正确的**（§三/§九：开发工具启动的窗口不得产出验收证据），**隔离检查必须保留**。
`panel.log` 里今天有 **4 次 `验收 Soak 已启动`**（09:54–09:59，venv 启动的窗口）⇒ 机制正常，
只要窗口跑在生产解释器上。

### 二、真缺陷 A：一个生产子进程**继承调用者的解释器**
`escalation_queue._wiring_problems()` 用 `sys.executable` 派生 `tools/check_wiring.py`，而它由**面板的泵**
驱动 ⇒ 开发工具启动的面板会**用产品不运行的那个解释器**判断产品接线是否合格。
**已改**为走 `runtime_env.resolve()`（项目自己的机制）；解析不到就返回 `None`（"无法运行"，不冒充答案）。
**诚实说明**：本次**没有改变结论**（`check_wiring` 不依赖第三方包，非生产解释器同样输出 `problems: 0`）
—— 这是**修掉一个隐患**，不是修掉报告的症状。

### 三、真缺陷 B：一致性检查的 `NameError`（**无 traceback，靠静态分析定位**）
任何 artifact 里都**没有** NameError 的 traceback（全仓日志/台账只有 2026-09-17 `is_dispatchable`、
2026-09-18 `fold` 两条历史）。按"不得猜"的要求，改用**静态分析**找未定义名字：

```
tools/control_panel.py:4023: undefined name 'view'
```

`_narrate_pump` 里 `development = view.get("current")`，而**该方法从未绑定 `view`**；两个兄弟刷新都写
`view = escalation_view()`，唯独这里丢了这一行。因为整块在 `try` 里、`except` 很宽，**NameError 被吞掉**
⇒ **一致性卡片每次刷新都失败且一言不发** —— 正是这个面板存在的意义所在的那种沉默。
**已补** `view = escalation_view()`。新增 `tests/test_panel_names_are_bound.py`（静态检查被监视的刷新方法
所用名字是否已绑定；**移除那一行 → 2 条测试立刻变红**，已验证）。
