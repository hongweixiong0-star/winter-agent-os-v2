## 01:38 全量测试改「分组跑」，并抓到我自己弄坏的一个测试

**单次全量在这台机器上永远给不出结论**：两次都跑到 100% 后**没有汇总行**就被宿主守卫打断
（`SAFE_DELETE_BULK_GUARD_ERROR exit 0xC0000142`；第二次守卫自己点出目标
`count=196 threshold=50`，是 pytest 自己累积的临时垃圾）。**没有汇总 = 没有结论**，
不许写成 PASS。

新增 `tools/run_tests_batched.py`：114 个文件分 **6 批**，每批**独立 basetemp**
（pytest 不再累积那堆垃圾）→ 读每批自己的汇总 → 聚合；某批仍无汇总就**拆半重跑**，
不原样再赌。每批输出落 `learning/tests_batched/<batch>.log`（否则聚合只能说「哪批失败」，
说不出**哪个测试**失败）。

- 第一次分组跑：`1231 → 1229 passed, 1 failed`，**batch3 真失败**：
  `test_runtime_interpreter.py::PreflightCommandTest::test_preflight_exit_code_follows_the_verdict`
  = `DEVICE_NOT_CONNECTED`。**是我这轮改坏的**：把设备纳入 preflight 的 core 判定后，
  那个测试变成「取决于 MuMu 是否恰好在运行」的脆弱测试。修法：探测打桩，
  并把契约两边都钉住——设备坏→退出码 1（拒启 AUTO）；网关拒绝→退出码 0（不阻止 AUTO，
  即用户第 3 条要求，从此由测试守住）。提交 `a49f8a0`。
- 重跑：**6/6 批 PASS，1231 passed / 0 failed / 7 skipped / 0 error，exit 0** → 全量门禁**关闭**。
