## 本轮做了什么

解除了"一条已死的开发验证记录永久占用设备、AUTO 一小时零步"的阻塞。commit `0322eaf`。

**两句根因**：

1. 跨进程版本断言的**形状不一致** —— 写入用 `after.head`（纯 sha），比对对手是
   episode 的 `repo_revision`（`head+digest`）。同一个 commit 实测出现两个 digest，
   比较**永不成立** ⇒ 账本全史 `validation_lease_requested 111 / version_active 0 /
   live_verified 0`，整条阶梯从未运行过。
2. **没有"版本已被超越"的出口** —— 选择器只看 `state`，于是每 2 分钟索取一次设备，
   30+ 次循环把 AUTO 一直挡在设备外。

**真机结果**：16:15 生产自己写出终结事件 → 16:15 租约归还 → 16:18 `GOAL_RUNNING`；
26 分钟内 **45 步 PRODUCTION、跨 6 个目标、verifier 通过 38/45**（修复前一小时 0 步）。

**另修**：读版本会抢 `.git/index.lock`（40 分钟 stale 锁挡住了所有 `git add`）——
两处读取改用 `--no-optional-locks`。诚实边界：**未证明锁的归属**。

**两条未通过（不冒充）**：
- 三兵营训练：`NAVIGATE_INFANTRY_CAMP` 卡在**识别**（那帧人眼是"盾兵营已选中"，
  但所有已注册模板全不匹配 —— 模板只覆盖 46 帧"金环"形态，这帧是另一种渲染）。
- 多角色切换：**不存在**；本轮找到了起点（设置 → Characters → Login/Confirm），
  以及两个不能碰的控件。
