# 从真机取一个"新的可观测事实"——固定流程

> 本文件是**操作流程**，不是项目事实的存放处（事实在 code / handoff / `docs/`）。
>
> 为什么需要它：操作者的产品定义要求智能体在角色成长后**自动发现新解锁的功能**
> （新产品定义 §19「Unknown UI → Check AccountStage → Safe Exploration → Identify Feature →
> Candidate Capability → Live Verification → Promote」）。那件事每发生一次，就要走一遍下面这套。
> 本项目已经用它加了：体力计、资源页签、情报入口、行军队列、**角色身份**。

## 顺序（顺序本身就是方法：先测量，再决定改不改）

1. **先确认这个事实画在哪里，别先想代码。**
   把候选位置**目视看一遍**（`PIL` 裁图 → 直接看）。
   2026-09-16 的例子：先假定"角色名在 HUD 上"，裁了三张帧（城市 + 世界地图）才确认**没有名字**，
   于是目标从"读 HUD"改成"找一个面板"。
2. **穷尽已能安全到达的地方。** 在决定做盲点之前，先搜语料里是否**已经有过**该页面的帧
   （按文件名、按 `page` 标注）。本轮搜到 0 张，才动手点。
3. **有界探针（这是唯一允许盲点的地方）。**
   写成 `tools/<name>_probe.py`，硬性自限：
   - 先读当前页，**不是 HOME/MAP 就 abort**，绝不从异常状态起手；
   - **只点一下**，且只点已量过坐标的控件；
   - **新页面里什么都不点**（新面板常含 `设置`/账号管理入口）；
   - 结果无法分类 ⇒ **有界 Back 一次**并再次确认回到已知页（把恢复本身也变成证据）；
   - 帧 + `probe.json`（含探针自己的自限条件）一起落盘。
4. **量出 ROI，不要拍脑袋给坐标。** 记录每个文本的**归一化中心 + 置信度**。
   行位置要靠**几何聚类**恢复（token box 是 ROI 局部坐标），不要为"这次刚好看到的那个名字"
   画一个恰好套住它的矩形。
5. **双证据门。** 只凭一个信号就认定页面，迟早会把别的页面读成它。
   本轮用「面板标题 `领主档案`」+「`账号：` 行」两件独立事实。
6. **归档到 `dataset/truth_audit/<set>_<date>/`**，写 `README.md` 说明**为什么**这些帧存在。
   ⚠ 测试**不得**引用 `dataset/raw` 或 `dataset/evidence`（可被清理，`test_evidence_integrity`
   会让整个套件失败）。复盘：这一条曾让我整轮测试变红。
7. **`.gitignore` 白名单**：`dataset/truth_audit/**/*.png` 默认被忽略，要放行就在
   `!dataset/truth_audit/<set>_*/**/*.png` 下加一行并写理由。
   ⚠ **不要**加 `dataset/raw/**/*.json`：那棵树里有 43 个**受控**标签语料。
8. **测试必须双向**：正向断言客户端画了什么，**负向断言别的帧什么都读不出**。
   负向那半边才是保护状态的东西 —— 把状态键到一个没人观测过的对象上，比没有状态更糟。
9. **改生产代码前先建两个总体。** 动手调阈值前，先量出"正确读数的分布"与"误读的分布"，
   并把**两个总体一起写进测试**（下次收紧或放宽都必须重新拿证据）。
   复盘：`SELECT_RESOURCE` 的门禁就是**低于它自己标定语料的最大值**，一直拒真。
10. **用不含被测机制的独立证据链复核一次结论**，尤其是要改"期望值"的时候。
    复盘：我两次差点把"能力提升"当成"回归"去改测试，都是靠独立扫描（只看可靠标签、不看锚点）
    裁决的；也靠它发现"pitch 157 与真机不符"这个**我自己编出来的**结论是错的。

## 反模式（都实际发生过）

- 从**缩略图目测**得出结论并写进文档（"真机 pitch 是 145–150"）—— 后来实测 157，纯属自造。
- 用**模板自己裁自己**当正样本（d=0 的循环论证，骗过三次真机运行）。
- 把 `failures=0` 当成套件健康（`errors≈16` 全在 setup，且落在"接下来碰巧在跑"的文件上）。
- 编辑工具报"成功"就以为改对了：`old_string` 截断到行中间会留残片、少结尾换行会并两行。
  **每次编辑后立刻 `ast.parse` 整个文件 + 读回改动区域。**
- **把一个"只在它自己被裁下来的那一帧上通过"的点击目标当成好的**（2026-09-16，`BTN_OPEN_DAILY`）。
  它 2026-09-08 注册、之后 8 天没人碰过，在真机上一直是 `SEMANTIC_TARGET_NOT_VERIFIED`，
  而**看数据看不出来**：模板匹配距离只有拿真机帧逐帧量才暴露（那帧 d=18，门禁 8，
  同一帧上城市其他按钮 d=0/8/8 全部命中 ⇒ 帧没问题，是模板过期）。
  **判定一个候选模板要三件事一起做**，缺一件就可能把"修好了"建立在错觉上：
  1. **在整棵语料上量**（`tools/probe_daily_entry_gate.py`，3480 帧），不要只看它自己的帧；
  2. **先定一个代理总体**当"这个控件应该在这里"的判据（本项目用同屏另一个稳定按钮，
     本轮是 `BTN_OPEN_EXPLORATION`），再同时报**召回**与**代理外命中**；
  3. **代理外命中要逐帧分类**，而不是看数字小就放过 —— 本轮那唯一一条
     `legacy_resource_search.png` 目视是城市帧（另一个账号、底部导航变淡），
     是代理看不见的**真阳性**，不是假阳性。
  ⚠ 代理本身要说清楚它是什么：城市与世界地图共用同一列左键与底部导航，
  所以那一列总体叫"HUD 帧"而不是"城市帧"，说成后者就是过度声明。
  ⚠ **不要用调门禁来"修"它。** 把阈值从 8 抬到 18 能让这一帧通过，
  但同时把一个召回率 **2.2%** 的点击目标留在生产里；换一个**排除角标**的裁剪
  （同一条记录同时覆盖"可领"与"已领"两种状态）把召回做到 **95.5%**。
  门禁是"两个总体之间的分界"，它的作用不是让某个候选通过。
- **角标/徽章第三次咬人（2026-09-16，第三次）**：`BTN_OPEN_DAILY`（红角标）、
  邮件角标，以及当天的 `TAB_DAILY_TASKS_SELECTED` —— 后者的第一版裁剪取整个胶囊
  `x 481..704`，**正好把右下角的红色可领角标（中心 ≈(688,1158)、r≈9）框了进去**，
  于是那次真机运行 13 帧里只命中 3 帧，**恰好是没有角标的那 3 帧**。
  ⇒ **注册任何点击/判定类模板前，必须先问一句：「这个控件会不会画角标/徽章？」
  会的话，把角标所在的那个角落排除出裁剪框**（裁剪改为止于 x=670 后，
  一条记录覆盖有/无角标两态，5 帧全 d=0）。
  ⚠ 这条要在**真机运行之后**再核一遍：注册时只有归档帧，角标状态可能恰好没出现。
  本轮就是靠「同一模板在一次运行里只命中一部分帧」这个现象反推出来的 ——
  **一次运行内命中率异常低，先怀疑"被观测控件有多个外观状态"，而不是先怀疑推理链。**
