## 一、本轮最重要的三个发现

### 1. `run_live.py` 下所有 `TAP_SEMANTIC` 技能直接崩溃（致命接线错误）

`LiveRuntime.resolve()` 使用 `self.semantic_vision.semantic.find(...)`，
而 `tools/run_live.py` 传入的 `semantic_vision` **已经是** `SemanticROIVision`
本身，所以第一个语义点击就抛：

```
AttributeError: 'SemanticROIVision' object has no attribute 'semantic'
```

真机复现：第一次运行 13 秒即退出，`episodes.jsonl` 一条都没写。
**这意味着控制面板的 AUTO 主循环在本次接管前无法完成任何一次语义动作。**
已修（`LiveRuntime._semantic` 属性访问器，兼容两种接线）。

### 2. 资源页签坐标是错的 → SELECT_RESOURCE 是最大失败源

页面真实结构（真机实测 720x1280）：

```
野兽 | 冰原巨兽 | 大型锯木厂 | 生肉 MEAT | 木材 WOOD | 煤矿 COAL | 铁矿 IRON
```

- 间距 **pitch = 157px**，选中格宽 **145px**，选中态由白色 L 角标标记
  （两条近白竖线，间距恒 144–145px）。
- **页签带的滚动偏移会变化**：客户端会把当前选中页签重新居中。
  本次会话实测到两种偏移：`0`（生肉在最左）与 `+400px`（野兽在最左）。
- 代码里的固定中心表 `{MEAT:0.25, WOOD:0.4722, COAL:0.6944, IRON:0.9167}`
  只对 `offset=0` 成立。在 `offset=+400px` 的会话里，点 0.25 实际选中的第 2 格
  **冰原巨兽**。

这解释了 `SELECT_RESOURCE` 44 次 3 成功（6.8%）与
`SEMANTIC_TARGET_NOT_VERIFIED` 中 `SELECT_RESOURCE` 占 40 次。

旧分类器还有一个无页面门控的误报：在**完全没有打开资源面板的 HOME 画面**上，
它返回 `RESOURCE_COAL_SELECTED` 且置信度 0.875。

**已重写**为：页面门控 → 白色角标锚点 → 相对布局(pitch) → 格内模板定身份 →
推算任意页签坐标（不在屏内则先滚动）。真机复算 **22/22 帧正确**，
分离度极清晰（选中态距离 ≤1.2，非选中态 ≥13.0）。

### 3. 采集链路在行军编队页永远停住

`RuleBrain.decide()` 对 `Page.MARCH` **只有野战分支**（`world.beast` 非空时），
采集编队页落到兜底 `registry.ready(world)[0]`，而注册表里第一个
`required_page=None` 的技能是占位技能 `WAIT`。
真机复现：`START_GATHER` 验证通过后，第 3 步选择 `WAIT`，运行以
`ENVIRONMENTAL_WAIT_NOT_PROVEN` 结束。

**已修**：新增 `Page.MARCH` 采集派兵分支；兜底逻辑排除 `WAIT` 这类占位技能。

### 关于 NEVER_TRIED 的重要更正

旧文档怀疑以下 Goal「完全没有真机证据」：
`EVENT_MINIMUM_GUARANTEE` / `USE_FREE_ARENA_ATTEMPTS` / `ALLIANCE_TIMED_EVENTS` /
`LABYRINTH_DAILY` / `PARTICIPATE_BEAR`。

用新的能力模型核实后：**它们不是 NEVER_TRIED，而是 BLOCKED / PARTIAL**——
真正的原因是**所需技能在注册表里根本不存在**（只在
`knowledge/skills/candidate/*.json` 里有设计稿）：
`OPEN_EVENT` `READ_EVENT_PROGRESS` `CLAIM_EVENT_TIER` `CHECK_ALLIANCE_EVENT`
`OPEN_ARENA` `READ_FREE_ATTEMPTS` `SELECT_ARENA_OPPONENT` `START_ARENA`
`VERIFY_ARENA_RESULT` `OPEN_LABYRINTH` 等。

这个结论比"从未尝试"更可行动：不是缺少尝试，是缺少实现。

### 旧覆盖率模型的问题

`GOAL_REQUIREMENTS` 用理想能力名（`READ_INTEL_LIST` / `SELECT_INTEL` / `EXECUTE_INTEL`），
真实注册表用（`OPEN_INTEL` / `SELECT_INTEL_BEAST_MISSION` / `DISPATCH_INTEL_BEAST`）。
两边词汇不同 → 已实现的算成缺失、没实现的算成满足。
现已替换为

```
Goal → Canonical Capability → Registered Skill → Production Evidence
```

映射文件：`knowledge/goals/goal_capability_map.json`（支持 ALL_OF / ANY_OF / VARIANT / SEQUENCE）。
`runtime_goal_status`（GoalLibrary 是否会发现它）与 `automation_coverage`（自动化能力占比）
分开统计。
