## 0. 操作者的总原则：零氪（F2P_CONSERVATIVE）

三家商店的所有规则都是同一条原则的落地：

**钻石是稀缺、不可再生的；时间是可再生的。任何「花钻石换时间 / 换分数」的自动化都不值得做。**

权威出处：`knowledge/resources/mechanism_cards.json` → `DIAMOND_POLICY`
（`"自动化默认禁止消耗钻石"`，status `CONFIRMED`），以及
`knowledge/strategy/goal_library_v1.json` 的 `"policy": "F2P_CONSERVATIVE"`。

由此推出的三家共同规则：

| 共同规则 | 说明 |
|---|---|
| **默认不花钻石** | 唯一例外：游荡商人的「钻石换统帅经验」在 operator_policy 里被单独点名允许（见 §1） |
| **只免费刷新** | `free_refresh_only: true`；`never_diamond_refresh: true` —— 一律不点付费刷新 |
| **规则没覆盖的情况 → 停下来问** | `uncovered_cases: STOP_AND_ASK`，不是「按常识猜一个」 |
| **没有名字就不判** | 三家商店的卡片都**不印物品名**，名字只能从卡片自己的 `确定购买` 弹窗里读 |

### 三家共同的 UI 事实（三份技能文件各自独立实测，结论一致）

- **购买是两次点击，不是一次**：点卡片本体 → `确定购买` 弹窗 → 弹窗上那颗橙色价格按钮 →
  客户端自己的 `购买确认` 对话框（「您是否要花费N钻石?」）→ **第二颗**橙色按钮才真正扣钱。
  只点第一下会以为买成了，其实交易还挂在确认框上 —— 只有钱包数字能证伪。
- **橙色按钮按「形状」定位，不是按面积也不是按数字**：`bbox [222,795,276,71]`
  （276×71，w/h ≈ 3.89）。同一页上「统帅经验」的金色六边形图标是 75×62（w/h 1.21，3,116 px），
  用面积阈值会把图标当按钮。第二颗按钮同样按 paint 定位 —— 曾经按「框里找数字」定位，在
  2026-10-05 04:13 让一笔已授权的购买以 `CONFIRM_BUTTON_NOT_FOUND` 落空、一分未花。
- **卡片点击区（实测 2026-10-05）**：`anchor+0 … anchor+80` → 打开 `确定购买`；
  `anchor-110 … anchor-30` → 只读的「拥有数量」浮层；再往外什么都没有。
  生产用的梯子覆盖 `+0/+15/+30/+45/+60/+80`，**任何坐标都不落盘**。
- **免费刷新控件只在其标签字面写着「免费」时才点。**
- **`press_back` 不是「返回上一级」**：连按六次会走出商店，弹出客户端自己的
  `确认退出游戏吗` 提示。恢复时要按它的 `取消`。
- **被中断的一轮会留下已 armed 的 `购买确认`**：只能用它自己的 `✕` 关掉，
  **绝不能**点它自己的按钮（那会直接花钱）。

## 1. 游荡商人（VISIT_WANDERING_MERCHANT）

**权威**：`knowledge/skills/VISIT_WANDERING_MERCHANT.json` → `operator_policy`

| 其它钻石报价 | **SKIP** |
| 规则未覆盖 | **STOP_AND_ASK** |

| 刷新 | 值 |
|---|---|
| 是否只免费刷新 | `free_refresh_only: true` |

  条带是**滑入**的，第一帧可能读不到页签文字（最多重试 3 次）。
- **卡片**：3 列 × 2 行 = **6 格**，列 x≈140/361/582，锚点 `剩余：N` 在 y=608（第 0 行）
  与 y=897（第 1 行）。

## 2. 神秘商店（VISIT_MYSTERY_SHOP）

**权威**：`knowledge/skills/VISIT_MYSTERY_SHOP.json` → `operator_policy`

| 规则 | 值 |
|---|---|
| 名称含 `英雄组件自选箱` **且** 折扣 = **50%** | **BUY** |
| 其它一切 | **SKIP** |
| 规则未覆盖 | **STOP_AND_ASK** —— 在这里只意味着一件事：**名字读不出来** |

| 刷新 | 值 |
|---|---|
| 是否只免费刷新 | `free_refresh_only: true` |
| 免费刷新次数 | **1 / 天** |
| 免费刷新次数（有艾格尼丝时） | **5 / 天** |
| 是否允许钻石刷新 | `never_diamond_refresh: true`（不允许） |

- **货币是金牌币，不是钻石。** 顶栏是 `钻石 …（x≈451）` 后面再跟一个金币数（x≈630，实测 3,290）。
  所以**钻石钱包不是这一页的支出见证** —— 用钻石做 verifier 会在一次完全正常的购买上
  报「(spent 0, expected 2,500)」。
- **折扣是硬门槛**：BUY 只能从**恰好 50** 到达，任何 badge 读失败（缺失 / 乱码）都落到 SKIP。
  没有 badge = 原价，operator 的「否则跳过」已经覆盖，**不要因此 ASK**（九格里有三格没有 badge，
  每格都 ASK 会把真正有 badge 的四格埋掉）。ASK 只留给「名字读不出来」。
- **入口 / 页签**：与游荡商人同一入口。实测页签坐标：游荡商人 x=98 / 神秘商店 x=302 /
  竞技商店 x=507 / 统帅市 x=684，均在 y=1241…1248。神秘商店有新货时带红点。
- **卡片**：3 列 × **3 行 = 9 格**（商人那页只有 6 格）。锚点 `剩余：N` 在
  y=609 / 898 / **1186**。第 2 行的**价格**落到屏幕外，但锚点和 badge 仍可读 —— 读不到价格的卡仍是卡。
- **点区必须夹紧**：第 3 行锚点在 y=1186，而页签条带从 1190 开始，
  所以未夹紧的梯子（+60/+80）会落到**别的商店的页签**上，一轮就会读着另一家店还以为自己在神秘商店。
- **免费刷新**在 x=596, y=314（绿色）。
- **刷新计数**：计在 `learning/shop_state.json` 的键 **`free_refresh_mystery`**
  （`tools/run_shop_mystery.py:37`，与商人的 `free_refresh` 分开计）。
  ⚠️ **诚实说明**：截至整理时，`learning/shop_state.json` 里只有
  `{"free_refresh": {"2026-10-05": 1}, "last_visit": "2026-10-04T19:12:10+00:00"}`——
  `free_refresh_mystery` 这个键**在代码里存在但从未被写入过**（因为免费控件还没被点过）。
  这是「代码事实」与「运行事实」的差别，不要把它当成已有计数。

## 3. 联盟商店（VISIT_ALLIANCE_SHOP）

**权威**：`knowledge/skills/VISIT_ALLIANCE_SHOP.json` → `operator_policy`

| 规则 | 值 |
|---|---|
| 名称含 `统帅经验` | **BUY** |
| 其它一切 | **SKIP** |
| 刷新 | **无需刷新** —— 商店按时自刷新 |
| 规则未覆盖 | 名字读不出 → 报 **ASK**，什么都不买 |

- **这一页不是从「商店」入口进的。** 路径是 HOME 底栏第 5 项 **`联盟`** →
  联盟页 2×4 磁贴网格里的 **`联盟商店`** 磁贴（实测中心 (246,938)）。
- **`on_alliance_shop_page` 必须同时满足两个条件**：商店页自己的 header 在顶部 12% 以内
  **且** 有 `下次刷新` 横幅。原因是联盟页自己的第三行磁贴也叫 `联盟商店` ——
  只看名字的页面判据会在两页上都成立。
- **页签**：今日 / 本周，位于 y=1241…1246（底栏条带内），所以点区夹紧在这里同样适用
  （第 4 行锚点贴近条带）。
- **网格**：3 列 x≈139/360/580；未滚动时行锚点 y=381/665/948，第 4 行被底栏裁掉。
  向上滑一次（从 (360,1050) 到 (360,420)）把第 4 行带到 y=1101，第二次滑不动了。
  `今日` 实测 12 格 / 4 行；`本周` 实测 9 格 / 3 行，下面还有被裁的一行。
- **货币**：顶部只有**一个**数字（x≈630，实测 81,403，后面跟绿色 `+`）。
  商店页那个 x≈451 的钻石槽**在这一页根本不渲染**。
  所以「把第一个数字当钻石」或「期待两个数字」的 verifier 会在一次正确的流程上报出胡话。
  ⚠️ 这个数是**联盟币还是钻石，尚未由一次购买确认过**。
- **弹窗**：`确定购买` 与另两家几何完全一致（橙色按钮 `bbox [222,795,276,71]`，
  中心 (361,831)，`✕` 在 (654,431)）。**这一页新出现的东西是一个数量滑块**
  （− / ‖ / + / 计数框 / max），默认数量为 1。
  **这个滑块绝不能碰**：实测一次误点 `+` 把金额从 4,000 变成了 20,000。
- **`英雄经验` 绝不能算作 `统帅经验`**（两个药瓶只差一个字）。

### 4.2 从未在真机上触发过的 BUY 分支

三家商店里，**只有一条 BUY 分支被真机证实过**（游荡商人「钻石换统帅经验」，两次，
均由钱包精确变动证实）。以下三条**规则成立、裁决触发过、但花钱路径从未走完**：

1. 游荡商人 · 资源换资源（`VERDICT_VERIFIED_PURCHASE_NOT_YET_MADE`）
2. 神秘商店 · 组件箱在 50%（`VERDICT_UNEXERCISED_PURCHASE_NOT_YET_MADE`，**50% badge 从未出现过**）
3. 联盟商店 · 买统帅经验（`VERDICT_UNEXERCISED_PURCHASE_NOT_YET_MADE`）

**不要把「共用代码」当成「已验证」。** 三条都与已验证的那条共用 `confirm()`，
但共用同一条代码路径 ≠ 在这页上量过。

### 4.3 STOP_AND_ASK 的精确边界

| 商店 | 真正要 ASK 的只有 |
|---|---|
| 游荡商人 | operator_policy 三条规则都没覆盖的报价 |
| 神秘商店 | **名字读不出来**（连「是不是规则点名的那个」都不知道） |
| 联盟商店 | 名字读不出来 |

「没有折扣 badge」**不是** ASK（没有 badge = 原价 = 规则里已写明的「否则跳过」）。
