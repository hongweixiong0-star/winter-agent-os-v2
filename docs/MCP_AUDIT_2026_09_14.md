# MCP 能力审计（2026-09-14）

结论先行：**本项目不新增任何 MCP。** 开发主循环（代码/git/ADB 真机/vision/pytest）
完全由原生工具 + 项目 venv + 项目脚本覆盖；宿主内置的 4 个 MCP 中 3 个与开发
流程无关或高危，全部按策略禁用于开发流程。用户层  保持为空。

## 现状

- 用户配置 MCP：0（ 不存在）
- 宿主内置 MCP：agent-mail / genie-baas / sheetagent / weixinpay
- 只读探针：agent-mail GetMe 实测通过（含 mail:send 权限——外发通道，需管控）

## 处置表

| MCP | 判定 | 策略 |
|---|---|---|
| agent-mail | 项目无关（外发通道） | 开发流程禁用；禁止经邮件发送项目数据 |
| genie-baas | 项目无关 + 数据外发面 | 禁用；episodes/evidence 是本地事实源，不上云 |
| sheetagent | 按需 | 仅在给操作者出分析表格时使用 |
| weixinpay | 高危无关 | 永久禁用于开发流程（真实货币红线） |

## 优先能力逐项裁决

| 能力 | 裁决 | 理由 |
|---|---|---|
| GitHub / 源码研究 | 不装 MCP | 公开仓库 git clone + WebFetch 即可；MCP 需 PAT，权限面与令牌风险零增益 |
| Context7 / 库文档 | 按需不装 | 依赖稳定，原生 WebSearch 覆盖 |
| Browser / Web Research | 不装 MCP | agent-browser skill 覆盖；装 MCP 即重复 |
| GitLab | 拒绝 | 无 GitLab 实例 |
| 本地代码搜索 | 拒绝 | 原生 Grep/Glob 足够 |
| SQLite / DB | 拒绝 | 项目不用 SQLite；云 DB 不接入 |
| HTTP / API 调试 | 不需要 | venv Python requests 覆盖 |

## 专家依赖

winter-agent-v2-dev **不声明任何 MCP 强制依赖**——不写入 plugin.json / .mcp.json。
（按操作者原则：可选 MCP 不得变成专家强制依赖。）

## 安全要点

1. 三个宿主 MCP（mail/genie-baas/weixinpay）都是**数据外发或资金面**——开发流程的
   使用策略已写入  的 mcp_audit 节。
2. 若未来确需引入 MCP：走  同样的门禁（来源/维护状态/权限/
   外发面/测试调用/登记），并只授予最小权限。
3. MCP 只提供工具；任何情况下不得借 MCP 引入第二 Scheduler/Registry/Runtime。
